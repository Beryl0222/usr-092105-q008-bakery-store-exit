# 烘焙门店退场清算平台

从品牌退场负责人的真实困局出发：储值金可以跨店消费、蛋糕定金进了加盟商私人账户、
冷柜属于租赁公司、中央工厂按未来七天备了料、员工最后班次和房租仍在按日产生。
平台先区分**经营主体与每一类权利义务**，再安排公告、顾客选择、订单转移、退款、
库存安全处置、设备归还、工资与供应商债务的先后顺序。

## 核心规则（引擎强制，违反即拒收命令）

1. **先主体、后处置**：品牌方、经营主体、加盟商、中央工厂、房东、租赁公司、供应商、
   邻店、员工组、顾客、支付平台逐一登记权利义务；资金所在账户
   （品牌监管户 / 门店经营户 / 加盟商私人账户）分账标记。
2. **公告先行**：闭店公告必须至少通过一个渠道发出，公告前不得登记清算事实。
3. **顾客选择必须本人确认**：邻店承接、退款、放弃均需顾客明确确认与时间；
   任何一方不得代选。订单转移还必须与顾客确认的邻店一致。
4. **承接必须校验产能**：邻店按日期 × 品类申报产能，占用达到上限拒入；
   邻店重新申报时已占用订单不丢失。
5. **支付先后顺序**：顾客退款 → 员工工资/经济补偿 → 房租 → 租赁费用 →
   供应商货款 → 加盟争议等剩余请求；高顺位有无争议未付款时低顺位支付被拒收。
6. **争议只冻结争议金额**：`可付余额 = 应付总额 − 争议金额`；加盟争议不得冻结
   其他顾客的无争议退款，争议裁定（全付/免除/部分）后按裁定金额结算。
7. **只追加，不改旧账**：工资与房租通过 `ACCRUAL_APPENDED` 持续计提；
   支付永远追加 `PAYMENT_SETTLED` 流水。
8. **食品安全红线**：食品只能邻店调拨（保质期内、有资质）、慈善捐赠（临保可食）、
   安全销毁（留证）、依约退货；**抵债转卖一律拒收**，处置款不得指定给债权人。
9. **冷链不断链**：店内仍有未处置冷链食品时，租赁冷柜不得归还。
10. **五道闸门全部通过才能最终关闭**：订单/顾客权益、食品安全、员工款项、
    租赁资产、供应商责任分别完成交接，且全部款项结清、争议有结论。

## 事件契约

四类聚合承载全部事实，事件只追加、版本按聚合从 1 递增：

| 聚合 | 承载 |
| --- | --- |
| `closure_case` | 公告、主体权责登记、邻店产能申报、最终关闭 |
| `customer_claim` | 储值金/蛋糕定金/预付订单登记、顾客选择、订单转移、放弃 |
| `inventory_disposition` | 食品分类与安全处置流；租赁资产逐台独立归还流 |
| `settlement_payment` | 应付义务、持续计提、争议、支付流水 |

- 信封与枚举：`contracts/domain.schema.json`
- 各事件 payload 字段约定：`contracts/events.md`
- 各方重复通知（会员推送、支付回调、对账单、租赁回执）携带同一
  `source_notice_id`，事件标识由其确定性派生，**只吸收一次**；来源系统重试安全。

## 代码结构

```
contracts/  事件信封 schema 与 payload 中文约定
src/
  validator.js   信封公共校验（枚举、版本、事件-聚合归属）
  event-store.js 只追加存储：event_id/通知幂等、版本连续、可选 JSONL 持久化
  projection.js  事件流折叠：未结清单（四桶 + 操作交接）与五道闸门
  engine.js      领域引擎：命令前置守卫，校验通过后构造并追加事件
  scenario.js    云栖店完整困局端到端演练（同时被测试复用）
tests/     契约与领域红线测试（node:test，零依赖）
```

## 未结清单（随事实投影，随时可重算）

- `awaiting_customer_choice`：等待顾客选择
- `awaiting_transfer`：等待邻店承接（含产能是否已申报）
- `awaiting_payment`：待支付（仅无争议/已决金额）
- `liability_disputes`：责任争议（争议金额单独冻结）
- `operational_handover`：未处置食品批次、未归还租赁资产

## 本地检查

```bash
node --test            # 19 项契约与领域规则测试
node src/scenario.js   # 云栖店完整清算演练（65 条只追加事件 → CASE_CLOSED）
```
